# 実験システム仕様書（SPEC）

[ ] の値は予備実験で決める仮の値。すべて `ExperimentConfig` に置き、エディタから変えられるようにする。

## 1. 実験の全体

| 項目 | 内容 |
|---|---|
| 比べるもの | 演出の違いによる理解度（学習効果）。主指標は空間理解の得点。テストは各授業の直後のみ（遅延テストなし） |
| 条件1 | テロップのみ（強調の時間だけ、同じ合計時間 Ttotal 停止する） |
| 条件2 | テロップ＋空間的強調 |
| デザイン | 被験者内。1人が授業①②を1本ずつ、片方を条件1、もう片方を条件2で受ける |
| 授業 | ①HDD の内部構造、②HMD の内部構造。どちらも7段階・部品6種・要点3つ・約8.5分 |
| 1人の流れ | 番号入力 → 事前テスト(PC) → HMD装着・練習 → 授業1本目 → 直後テスト・質問紙(PC) → 休憩 → 授業2本目 → 直後テスト・質問紙(PC) → 自由記述 |
| 入力 | Quest 3 のコントローラー（ハンドトラッキングは対象外） |
| 教室 | 理科実験室（実験台が並ぶ部屋、`docs/room_reference.png`）。Polycam で実在の部屋をスキャンし、glTF で取り込む（全条件で同じ）。詳細は 1.1 |
| 学び方 | 受講者が3D部品を自分で動かし、分解・組み立てをしながら、説明・解説の音声を聞く。要点では演出を受け取る |

### 1.1 教室（理科実験室）

- 受講者は実験台の1つの前に立つ（または座る。予備実験で決める）。授業の部品はその実験台の天板に置く
- スキャンしたメッシュは凹凸があるので、部品を置く天板と床には、別に平らな Collider（BoxCollider など）を重ねる。スキャンのメッシュには当たり判定を付けない
- 仮想の実験台の高さと、受講者の床の高さを合わせる（Editor か起動時のキャリブレーションで調整できるようにする）
- 黒板・テレビ・棚などは背景として使うだけで、操作の対象にしない

テストと質問紙は PC で回答する（Unity アプリの対象外）。アプリが担当するのは、HMD を装着してから外すまで。

## 2. 参加者の割り当て

参加者番号 `id`（正の整数）を4で割った余りで、授業と条件の順番を決める。

| id mod 4 | 1本目 | 2本目 |
|---|---|---|
| 1 | ① HDD・条件1 | ② HMD・条件2 |
| 2 | ② HMD・条件1 | ① HDD・条件2 |
| 3 | ① HDD・条件2 | ② HMD・条件1 |
| 0 | ② HMD・条件2 | ① HDD・条件1 |

- 番号は `participants.csv`（id の一覧）に登録されたものだけ受け付ける。未登録なら警告して再入力
- `participants.csv` は `Application.persistentDataPath` に置く（Quest へは adb で送る。ビルドし直さずに変えられる）。1行に1つの id、1行目は見出し「id」でもよい。空行と「#」で始まる行は無視
- 氏名は扱わない。ログにも番号だけを残す

## 3. 授業の流れ（状態遷移）

授業の中身は `LessonData`（ScriptableObject）で定義し、HDD と HMD で同じプログラムを使う。

`StageData` の項目：段階名、対象部品、説明音声（AudioClip）、解説音声（AudioClip、任意）、テロップの文言、完了条件（外す／付ける／触れる／なし）、要点かどうか（bool）

- 説明音声：そのパートで何をするか（例：「アームを外して、円盤の上に何があるか見てみましょう」）。操作の前に流す
- 解説音声（任意）：要点の仕組みの解説。強調（条件1は停止）の間に流す。**両条件で同じ音声・同じタイミング**にする。長さは Ttotal 以内にそろえる

1本の授業の状態：

1. **授業開始**：条件と授業データを読み込む
2. **説明音声**（パート i）：再生中は部品を掴めない
3. **操作受付**：音声が終わったら掴めるようにする
4. **完了判定**：正しい位置・向きに付けた（または外した・触れた）ら完了。学習者パネルと実験者操作は5章
5. **要点か？**：要点でなければ 8 へ
6. **注視判定**（4.1）→ 見ていなければ再配置（4.2）。**条件1・条件2の両方で行う**
7. **強調**（4.3）：元の状態を保存 → 掴みを無効化 → テロップ表示・解説音声の再生 → 条件2は空間的強調／条件1は Ttotal 待つ → テロップを消す → 掴みを戻す
8. **最後のパートか？**：まだなら i+1 で 2 へ
9. **組み立て確認**：完了をログに記録して授業終了。「HMD を外してください」と表示。`requireAllSocketsFilled`（初期値 true）が true なら、全ソケットに正しい部品が入っていることを確認してから終了する

- 要点の対象は部品1つとする

「操作完了」と「強調終了」は別々の出来事としてログに残す。

## 4. アルゴリズムと式

### 4.1 注視判定（頭の向きで推定。視線追跡は使わない）

θ = arccos( (f・d) / (|f||d|) )　…　Unity では `Vector3.Angle(f, d)`

- f：HMD の正面方向、d：頭の位置から対象部品の中心へのベクトル
- θ ≤ θth の状態が t_hold 続いたら「見ている」
- t_timeout たっても見なければ再配置
- N 回を超えて注視に失敗したときは、テロップのみを **Ttotal の間**表示する（条件2でも空間的強調はしない）

| 名前 | 値 |
|---|---|
| θth | [20]° |
| t_hold | [0.3] 秒 |
| t_timeout | [3] 秒 |
| 再配置の上限 N | [2] 回（超えたら強調せずテロップのみ表示し、失敗をログに記録） |

### 4.2 再配置

p_new = p_h + D × f / |f|

- p_h：頭の位置、D：[0.6] m。部品の向きは変えない
- f は HMD の正面方向を**水平面に投影したもの**（y 成分を 0 にして正規化）。見下ろしていても天板にめり込まない。高さは頭の高さ p_h.y を使う
- 他の部品と重なる場合は、[0.1] m ずつ奥へずらす（上限 [10] 回。超えたら最後の位置に置き、ログに記録）
- 再配置した部品は、強調の④復帰で**再配置する前の元の位置**（操作完了時点の位置）へ戻す

### 4.3 空間的強調（条件2のみ。4段階を1つずつ順に実行）

| 段階 | 内容 | 値 |
|---|---|---|
| ① 引き寄せ | 元の位置 p0 から、正面 D の位置 pt へ移動。正面は 4.2 と同じく水平。頭から dmin 以上離す | T1 = [1.0] 秒、dmin = [0.4] m |
| ② 拡大 | 見かけの大きさが視角 φ になる倍率 s へ | T2 = [0.5] 秒、φ = [30]° |
| ③ 回転 | その場で鉛直軸まわりに1回転 | ω = [45]°/秒（約8秒） |
| （観察） | 拡大したまま止め、受講者が頭を動かして回り込んで見る | `useObservePhase`（初期値 false）、T_obs = [3] 秒 |
| ④ 復帰 | 逆の動きで元の位置・大きさ・向きへ | T4 = [1.0] 秒 |

- 引き寄せ：p(t) = p0 + (pt − p0) × e(t)、e(t) = 3t² − 2t³、t = 経過時間 / T1（0→1）
- 拡大：s = 2D × tan(φ/2) / w。w は部品を包む球の直径（Renderer の bounds から求める）。倍率の変化にも e(t) を使う
- s < 1 になる場合は s = 1 に制限する（縮小はしない）
- p0 は再配置する前の元の位置。手に持っている部品は強制的に離し、ソケットに付いている部品は一時的にソケットから外して動かし、④復帰でソケットに戻す
- Ttotal = T1 + T2 + 回転時間 + (観察時間) + T4。条件1はこの時間だけ止める
- 強調中は全部品の掴みを無効にする

### 4.4 テロップ

- World Space の Canvas ＋ TextMeshPro。対象部品のすぐ上に出し、常に受講者の方を向かせる
- 強調中に部品が動くとき、テロップを部品について動かすかは `telopFollowsPart`（初期値 true）で切り替える
- 日本語フォントの TMP Font Asset が必要（Noto Sans JP など）
- 字幕（説明音声の全文）は出さない。要点のパートでだけ表示する

### 4.5 音

- 説明音声：`spatialBlend = 0`（2D）。頭の向きで左右差を出さない
- 操作音（吸着した音など）：部品の位置から鳴る 3D 音

## 5. 部品操作と補助

### 5.1 掴む・付ける

- 部品：Collider ＋ Rigidbody ＋ XR Grab Interactable
- 付ける場所：XR Socket Interactor。正しい部品だけを受け付け、向きのずれ（`Quaternion.Angle`）が [15]° 以内なら吸着
- 精度は粗くてよい（[0.05] m 以内で吸着）。組み立てられることが目的で、細かい操作の巧さは問わない
- 円盤など回転対称の部品は、部品ごとの設定 `ignoreSymmetryAxis`（対称軸を指定）で、その軸まわりの回転を向きの判定から外せるようにする

### 5.2 学習者パネル（VR 内）

| ボタン | 動作 |
|---|---|
| リセット | 対象部品を元の位置に戻す（落とした・見失ったとき） |
| ヒント | 正しい場所を光らせる。押した回数をログに記録 |

### 5.3 実験者の操作（PC のキーボード）

| キー（仮） | 動作 |
|---|---|
| S | スキップ（そのパートを自動で完了。ログに記録） |
| P | 一時停止／再開（強調中なら部品を元の状態に戻し、再開はパートの最初から） |
| A | 授業の中断（その授業は分析から除外。ログは保存） |

- [60] 秒でヒント・[120] 秒で自動完了のタイマーは `useAutoTimers`（初期値 false）で切り替えられるようにしておく
- HMD を外した・トラッキングを失ったときは自動で一時停止する

## 6. ログ

保存先：`Application.persistentDataPath/<id>/`。出来事ごとに追記してフラッシュする。1人1ファイルで、2本の授業を同じファイルに追記し lesson 列で区別する。文字コードは UTF-8（BOM 付き）

**events.csv**

| 列 | 内容 |
|---|---|
| time | 授業開始からの秒（小数3桁）。一時停止中の時間を含めるかは `timeExcludesPause`（初期値 false＝含める）で切り替える |
| unix_ms | 実時刻 |
| participant, group, lesson, condition | 番号、余り、HDD/HMD、1/2 |
| stage, part | 段階番号、部品名 |
| event | 下の一覧 |
| detail | 補足（θ、回数など） |

event の一覧：lesson_start, audio_start, audio_end, grab, release, socket_ok, reset, hint, skip, op_complete, gaze_ok, gaze_timeout, relocate, gaze_fail, emphasis_start, emphasis_phase, emphasis_end, pause, resume, abort, lesson_end

**head.csv**（[10] Hz）：time, lesson, pos_x, pos_y, pos_z, rot_x, rot_y, rot_z, rot_w, theta。判定対象がないときの θ は空欄

## 7. 分析（`analysis/`）

| 指標 | 計算 |
|---|---|
| 理解度 | 区分（記憶・空間理解・応用）ごとの正答率。伸び G = 事後 − 事前 |
| 効果量 | dz = X̄diff / SDdiff（差は 条件2 − 条件1）、小標本補正 gz = J × dz、J = 1 − 3 / (4(n−1) − 1) |
| 検定 | 対応のある t 検定：t = X̄diff / (SDdiff / √n)、自由度 n−1 |
| 認知負荷 | NASA-TLX（WWL 法）の総合得点 |
| 酔い | SSQ（下位尺度ごとに重みを掛けて合計） |
| ログ | 授業時間、ヒント回数、スキップ回数、再配置回数、注視失敗の件数を条件別に集計 |

- テスト・質問紙の生データは CSV で用意する（列の形は実装時に決める）
- **SSQ の項目と下位尺度の対応表・重み、WWL の手順は、原典から用意した表（`analysis/tables/`）を読み込む。推測で書かない**
- 順番（1本目／2本目）と授業（HDD／HMD）の偏りも確認できるようにする
- 参加者数は4群でそろわなくてもよい（カウンターバランスの均等は考慮しない）
- 事前テスト・直後テスト・質問紙（SSQ を含む）は授業後に別の媒体で実施する。アプリには組み込まない
